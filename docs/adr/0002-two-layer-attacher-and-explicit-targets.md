# Two-Layer Attacher Core, Explicit Targets, 5.0 Defaults, and Pruning Tautological Options

In 4.4 and completed in 5.0, `ember-attacher` uses a shared `.ts` `AttacherCore` backing three public entry points—`{{tooltip "Text" class="..."}}` (backed by a document-scoped singleton **Attachment** pool), `<Attacher as |a|>` (headless primitive), and `<AttachTooltip>` / `<AttachPopover>` (supporting `@target`, yielded `{{a.target data}}`, `<:target>`/`<:content>` blocks, and `[popovertarget]` / `[interestfor]` pairing)—authored in native `.gts` / `.ts` with compiler-emitted `.d.ts` declarations as the single type authority.

In 5.0, `<BasicAttacher>` and all deprecated 4.x arguments and aliases (`@explicitTarget`, `reference`, `setReference`, `@flip`, `@overflowPadding`, `@floatingUiOptions`, `@floatingElementContainer`, `@isOffset`, `@style`, `@additionalClass`, `@onInitializeAttacher`, `@onWillDestroy`, `@configKey`) are removed; `<AttachPopover>` defaults to `{ showOn: 'click', hideOn: 'click clickout escapekey', interactive: true, lazyRender: true }`; `@autoUpdate` defaults to `true`; tooltips default to `@interactive={{true}}` (WCAG 1.4.13 hoverable content); and `AttachmentAriaController` applies smart `aria-labelledby` / duplicate-description suppression / open-only `aria-describedby` semantics.

We rejected (a) dropping `<AttachTooltip>` and `<AttachPopover>` in favor of `<Attacher @as="...">` alone, which would cause unnecessary template churn across existing callers, and (b) defaulting missing **Targets** to `document.body` in 5.0, which breaks `clickout`, attaches page-wide **Triggers**, pollutes `body[aria-describedby]`, and fails in SSR. In 5.0, `<AttachTooltip>` and `<AttachPopover>` assert in debug builds when initial mount has no target binding (while permitting nullable reactive `@target={{this.dynamicTarget}}`) and remain inert in production and SSR.
